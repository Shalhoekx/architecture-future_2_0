# Обоснование конфигурации Terraform + Docker

## Выбор технологий

Infrastructure as Code (IaC): Воспроизводимость и Масштабируемость

### Воспроизводимость
 - Декларативность: Инфраструктура описывается кодом, что гарантирует создание идентичных сред (dev/staging/prod) без "дрейфа конфигураций"

 - Версионирование: Код хранится в Git, позволяя откатываться к любой версии инфраструктуры

 - Автоматизация: Устраняет "человеческий фактор" и ручные ошибки при развертывании

 - Документированность: Код сам выступает документацией состояния инфраструктуры

### Масштабируемость

 - Модульность: Повторное использование компонентов (например, модуль для создания VM с предопределенными параметрами)

 - Параметризация: Изменение масштабов через переменные (одна строка кода вместо ручной настройки 100 серверов)

 - Идемпотентность: Безопасное многократное применение конфигураций без побочных эффектов

 - Автомасштабирование: Интеграция с облачными провайдерами для динамического изменения ресурсов под нагрузку

## Ресурсы
Автоматически разворачивается вся необходимая конфигурация: network, disk, computed cloud VM, container registry. 
Для VM выделено 2Gb оперативной памяти, 2 ядра процессора и 15ГGb диск - этого вполне достаточно для работы одного 
инстанса небольшого приложения витрины в Docker.
